# Бренд-гайд Водоворот

**Водоворот** (_Vodovorot_) — Telegram-бот для раскладов Таро. Этот документ задаёт, **как мы говорим с человеком** и **как выглядит готовое толкование** в чате.

Реализация формата ответов модели: `src/brandFormat.ts` → `prompts.ts`; общий тон и язык: `src/ai.ts` (`SYSTEM_PROMPT`). Сообщения самого бота (приветствие, ожидание, ошибки): `src/botCopy.ts` и `src/bot.ts`. Фразы про **границу календарных суток** и время рассылки (без сырого IANA в чате): `src/calendarDayUserPhrases.ts`; сводка для пользователя: **`/status`** (`src/statusCopy.ts`). Пресеты времени рассылки: `src/dayPushPresets.ts`, клавиатура — `src/botKeyboards.ts`.

**Профиль бота в Telegram:** поля About, Description, Privacy Policy URL и команды — в [docs/BOTFATHER.md](BOTFATHER.md) (формулировки **деловые, без рекламного тона**); политика для URL — [docs/PRIVACY.md](PRIVACY.md).

---

## 1. Голос бота (то, что пишет Водоворот в чате)

- **Простой русский:** как в разговоре с знакомым, без канцелярита и без слов из разработки.
- **Обращение на «ты»** — во всех системных сообщениях из `botCopy.ts` и в ответах об ошибках; единый тон с приветствием `/start`.
- **Уважение и ясность:** не запугивать и не заискивать; можно коротко объяснить, что происходит.
- **Честность:** толкование — не предсказание судьбы; без обещаний событий и без медицинских, юридических и финансовых советов.
- **Техника:** не раскрывать, что «ответ пишет программа» или из какого сервиса он приходит.

---

## 2. Голос толкования (текст по картам)

Текст генерируется по правилам ниже и должен **легко читаться в Telegram**:

- **Язык:** только русский, без английских вставок и без «модных» калек.
- **Ритм:** в основном короткие и средние предложения; в одном абзаце — одна главная мысль.
- **Тон:** спокойный, взрослый; без лести, без крика и без давления «срочно сделай»; без мета-фраз («как модель», «в этом ответе»).
- **Маска-рассказчик** (случайный старший аркан в промпте): смягчает угол зрения внутри текста, но **пользователю имя маски не показывается**; не начинать ответ с объявления персонажа.

Подробные запреты по содержанию — в промптах (`prompts.ts`).

---

## 3. Вёрстка в Telegram и «маркдаун»

**Почему не MarkdownV2.** В Bot API «Markdown» по сути — **MarkdownV2**: почти каждый спецсимвол нужно экранировать. Текст от языковой модели легко ломает разметку. Для пользовательского контента удобнее **`parse_mode: HTML`**: экранируются только `&`, `<`, `>` — это предсказуемо и делается в коде (`readingTelegramHtml.ts`).

**Как повышаем читабельность толкования**

| Приём                           | Зачем                                                                                                                                                              |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Полужирные метки**            | Строки-заголовки ровно из списка `READING_SECTION_LABELS` в `brandFormat.ts` оборачиваются в `<b>…</b>` — глаз цепляется за структуру. В конце метки **нет** тире. |
| **Пустая строка между блоками** | Уже в тексте модели; в HTML-режиме перевод строки даёт визуальный разрыв между абзацами.                                                                           |
| **Короткие абзацы**             | Задаётся промптом; в узком чате это важнее, чем курсив.                                                                                                            |
| _Опционально позже_             | Редкий `<i>…</i>` для имён карт в теле — только если не путает модель; сейчас не включено.                                                                         |

Сообщения самого бота (приветствие, «секунду…», ошибки) можно оставлять **без** разметки или точечно добавить, например, `<b>Водоворот</b>` в приветствии — по желанию, с тем же HTML и экранированием.

**Инвариант для модели:** в ответе **нет** сырого HTML и нет символов `* _ < > &` для самодельной разметки — только структура из бренд-гайда; оформление меток добавляет код.

## 4. Формат ответа «На день» (одна карта)

| Шаг | Что в чате                                                                                                                                                                                                                          |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Первая строка — **только имя карты**, если она в обычном (прямом) положении; если **перевёрнута** — `Имя карты (перевёрнутая)`, как формирует код (`formatDrawnLine`). Прямое положение не подписываем: это состояние по умолчанию. |
| 2   | Пустая строка.                                                                                                                                                                                                                      |
| 3   | Отдельная строка ровно **`О чём здесь речь`** (без тире в конце), затем 1–2 абзаца: что означает карта в контексте дня, простым языком.                                                                                             |
| 4   | Пустая строка.                                                                                                                                                                                                                      |
| 5   | Отдельная строка ровно **`Коротко о дне`**, затем **один** абзац: сжатый вывод без призывов к действию.                                                                                                                             |
| 6   | Пустая строка и **короткий финальный абзац без новой метки** (как в промпте `brandFormatDayPromptBlock`): нейтрально, что это повод поразмыслить, а не приговор — **один раз**, без повторения в блоках выше.                        |

Не добавлять другие заголовки, `#`, списки и нумерацию разделов; перед первой меткой не вставлять вступлений.

---

## 5. Формат ответа «Прошлое — настоящее — будущее»

Строгий порядок блоков (каждая метка — отдельная строка **без тире в конце**, затем абзац; между блоками — пустая строка):

1. **`Прошлое`** — один абзац о карте прошлого; о положении (перевёрнутость) пиши **только** если эта карта действительно перевёрнутая.
2. **`Настоящее`** — один абзац (то же правило про ориентацию).
3. **`Будущее`** — один абзац (то же правило).
4. **`Как это сходится`** — 1–2 абзаца: общая связка трёх карт.
5. Пустая строка и **короткий финальный абзац без метки** (`brandFormatSpreadPromptBlock`): размышление над картами не равно приговору — спокойно, один раз.

Перед **`Прошлое`** не должно быть приветствий, названия расклада и т.п.
